# DYD-734 callback interrupt proof

Base: `0086bc8d05900442aca84eb46793791635c70ab3`. Red-test commit: `9812256e`.
Writer: code-writer/model: gpt-6-astra. CPython: 3.14.4, Linux.

The regression sends a real `SIGINT` from `_row` while the registered witness callback is
active at the subject's loop condition. The handler raises either `KeyboardInterrupt`
or `RuntimeError`. Target and non-target subjects must both return `ADAPTER_INTERRUPTED`.
The old runtime instead returns the outer harness's `ESCAPED` in all four cases.

CPython v3.14.4 `Python/ceval_macros.h:321-334` explains the failure: when
`_Py_call_instrumentation_jump` fails, `INSTRUMENTED_JUMP` sets `next_instr = dest + 1`
before exception lookup. The destination can be outside the source branch's `try`.
Disabling non-target BRANCH callbacks does not fix target code or the first non-target callback.

The witness now uses INSTRUCTION events, whose errors unwind at the executing instruction.
It enables instruction events only for target code, reconstructs native BRANCH offset pairs,
disables irrelevant instruction sites, and clears
pending frame edges on exception handling/unwind and shutdown. PY_START and LINE accounting
remain unchanged. No signal handlers are replaced or exceptions deferred by production code.

The independent accounting test compares complete public rows with a native BRANCH monitor:
conditionals, loops and breaks, recursion, interleaved generators, async comprehensions,
iterator exceptions, physical ownership and EXTENDED_ARG jumps. A separate test checks
interrupted pending-edge cleanup and frame release.

Before final gates, an additional explicit async-iterator probe found that the initial
implementation `d1031f96` reported END_SEND rather than NOT_TAKEN as the successful edge's
origin. CPython's LINE instrumentation at SEND's target explains that distinction. The
retained accounting corpus now includes explicit StopIteration/StopAsyncIteration and
plain async-for; the corrected mapping matches native public rows. The superseded coverage
run was deliberately interrupted (exit 130), and its queued static command canceled
(exit 143). Neither is a passing gate. Their logs remain `coverage.log` and `static.log`;
successor gates use separate names.

The first completed whole-Python gate (7769bcbb, 1,185 tests, 58 platform skips) found two
accounting-oracle failures under nested measurement. Global instruction events transiently
changed a separate native monitor's branch origins for non-target code. A retained nested
witness test reproduces that failure without a whole suite. Instruction events are now local
to target code and are cleared by CPython's free_tool_id; non-target signal injection exercises
the remaining LINE callback. `local-red.log`/`local-green.log` preserve that correction's
exits 1/0, and `coverage-final.log` retains the failed gate. Later gates use new names.
