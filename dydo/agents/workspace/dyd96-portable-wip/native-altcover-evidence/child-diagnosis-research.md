# DYD-96 AltCover child aggregation diagnosis

**DECIDED — answer:** the missing child hits are an AltCover 9.0.102 aggregation defect, not a fixture or report-path error. The default recorder writes one buffered `Table` per process. The shipped runner's compiled C# `AddTable` only copies a module while that module key is absent, so the first spool wins and every later spool for the same instrumented module is discarded. The documented `--eager` prepare option is a supported fix for this fixture: it writes visits immediately rather than as end-of-process tables, and the same parent → child run then collects all 24 visits and the exact child-only lambda/branch. Keep `G = 2` until that invocation is separately specified/reviewed and the retained integration/full-suite proof passes.

## Exact defect and supported fix

Pinned official source is commit `b698a5c2daa26ceb0723858914812538b6c10e81`. The runner enumerates every `report.*.acv`, folds them into one dictionary, and calls `Counter.AddVisit` for each decoded record ([`Runner.fs` lines 994–1129](https://github.com/SteveGilham/altcover/blob/b698a5c2daa26ceb0723858914812538b6c10e81/AltCover.Engine/Runner.fs#L994-L1129)). The build actually compiles `AltCover.Recorder/Base.cs` into `AltCover.Base` ([project line 20](https://github.com/SteveGilham/altcover/blob/b698a5c2daa26ceb0723858914812538b6c10e81/AltCover.Base/AltCover.Base.csproj#L20)). In that C# `AddTable`, the entire point loop is inside `if (!counts.ContainsKey(key))`; once spool 0 adds the module, spool 1's same module is skipped ([`Base.cs` lines 462–490](https://github.com/SteveGilham/altcover/blob/b698a5c2daa26ceb0723858914812538b6c10e81/AltCover.Recorder/Base.cs#L462-L490)). This exactly predicts the isolated and combined reports.

Official usage documents `--eager` as “writes runner-mode coverage data immediately” and separately documents `--save`/`runner --collect` ([usage lines 98–119](https://github.com/SteveGilham/altcover/blob/b698a5c2daa26ceb0723858914812538b6c10e81/docs/Usage.md#L98-L119), [lines 159–161](https://github.com/SteveGilham/altcover/blob/b698a5c2daa26ceb0723858914812538b6c10e81/docs/Usage.md#L159-L161), [lines 242–268](https://github.com/SteveGilham/altcover/blob/b698a5c2daa26ceb0723858914812538b6c10e81/docs/Usage.md#L242-L268)). The recorder source confirms eager runner mode calls `TraceVisit` for each hit instead of buffering through `AddVisit` ([`Recorder.cs` lines 685–699](https://github.com/SteveGilham/altcover/blob/b698a5c2daa26ceb0723858914812538b6c10e81/AltCover.Recorder/Recorder.cs#L685-L699)). With only `--eager` added at instrumentation, the unchanged parent → child command finds two spools, records `11 + 13 = 24`, and `eager-collected.xml` reports main token `100663297` sequence `17/21`, branch `4/6`; executed child lambda `100663301` sequence `1/1`, branch `1/2`; never-invoked lambda `100663302` sequence `0/1`, branch `0/2`.
