# DynaDocs — Documentation Root

Documentation is agents' long-term memory: a source of truth that outlives every session, and a
guiding light through the fog of implementation. Keep it true — a stale doc misleads everyone who
comes after you.

- [understand/](understand/_index.md) - what this project is and how it is built: start at
  [about](understand/about.md), what this project stands for.
- [guides/](guides/_index.md) - how to work here: the procedures and standards work is held to.
- [reference/](reference/_index.md) - exact rules and specifications;
  [about-dynadocs](reference/about-dynadocs.md) explains the machinery: skill compilation, the
  guard, the scaffold.
- [project/](project/_index.md) - what was decided and what happened: Decision Records, plans, evidence,
  release history, pitfalls, and FutureFeatures.
- [dydo glossary](reference/dydo-glossary.md) - locked definitions of how work is named: the Linear
  work graph, fog and question Issues, roles and skills, evidence - and the retired PM terms to avoid.
- [glossary.md](glossary.md) - this project's own domain vocabulary.

About to write or edit any doc? [Writing docs](reference/writing-docs.md) is the contract it is
held to.
