# dydo 3.0 Skill Craftsmanship Assimilation

Project 6 restored the shared agent methods before dydo 3.0 ships. The result is one authored skill
system compiled into Claude and Codex artifacts: 15 canonical `skill-*.template.md` sources, 15
project-local copies, 15 skills per runtime, and five worker-agent definitions per runtime. The shared
entry prompt is again limited to project orientation and the Linear-live/Git-durable boundary.

## What changed

- Authored role templates use `skill-<name>.template.md`. The migration preserves modified or custom
  legacy `mode-*` files and activates only the new name; stock framework-owned files migrate with their
  hash ownership.
- The mature dydo roles were reduced against the selective `0f06c947` baseline without reviving the
  retired local work graph. The full kaizen method remains in Self Improvement; Chief of Staff and
  Orchestrator retain only their role-specific routing sentence.
- Wayfinder and Grilling were rebuilt from Matt Pocock's originals at pinned revision
  `6654f6b60cd9d5be8b54c6fafe44346dabeb3b76`. Bro regained its missing context and language method;
  Grill Me is an explicit wrapper; Writing for Agents is the only new upstream-derived skill.
- Neutral `invocation` metadata now compiles to native runtime controls. Bro, Grill Me, and Wayfinder
  are explicit-only in Claude and Codex; automatic skills omit those restrictions. Authored
  descriptions pass through unchanged.
- Matt-derived text is attributed in source comments and identical root/npm third-party notices, both
  of which are included in their respective packages.

## Integrated proof

The integrated candidate starts from exact merged base
`c0a0c01769a0466518dd7f911480e6c9c2783971`. Source-built sync produced 53 files across
`.agents/skills`, `.claude/skills`, `.claude/agents`, and `.codex/agents`; a second sync produced the
same closed path set and byte-identical SHA-256 values. The path/hash manifest digest is
`CA84BD801ABACEA7C8DBA8F55607549816E840D15CD69CC37CEE5BF66DF8F4F4`: sort files by full path,
serialize each as `<Windows-relative-path>|<uppercase-SHA-256>`, join with LF and no terminal newline,
then hash the UTF-8 bytes.

Template reconciliation changed exactly the 15 skill-template framework hashes. Its following
`template update --diff` reported zero pending updates. `dydo validate` and `dydo check` both returned
zero errors and zero warnings. The Release build returned zero warnings and zero errors; the isolated
full suite passed 1,803 of 1,803 tests; forced coverage passed all 70 modules. `git diff --check`
remained clean.

Disposable package inspection proved that both `dydo.3.0.0.nupkg` and `dydo-3.0.0.tgz` contain
`THIRD-PARTY-NOTICES.md`; the two notice files are byte-identical at SHA-256
`931B2D98BC403CC9D2299AF6C1B6FF6ED315D540F302A75C5DA0E8E5E2496075`. The package artifacts were
removed after inspection.

## Observed friction

- Project-local template overrides are real source inputs, not disposable generated copies. The naming
  migration had to distinguish stock hash-owned files from modified or custom legacy files; silently
  deleting or compiling the latter would have destroyed user intent.
- Several exact-wording tests had become guardians of the prompt sediment being removed. Reviewed
  chronological amendments widened P6-2, P6-3, and P6-4 only to replace those stale assertions with
  parity and behavior checks. This is why future skill tests should prove structure, invocation, and
  role boundaries rather than freeze prose.

## Acceptance boundary

The independent integrated-systems audit and the separate fresh craftsmanship review both returned
**PASS — zero findings** on the exact generated candidate and this record. Together they verified the
merged plan, exact 47-file delivery scope, runtime metadata, idempotence, packages, tests, every authored skill,
the entry prompt, selective `0f06c947` continuity, and direct fidelity to upstream `6654f6b6`. No prose
defect was routed back to a source lane, and this lane hand-edited no generated output.

This Project does not release, tag, publish, restructure the documentation tree, or change the live-work
ontology. Linear remains the live work graph; Git and dydo remain durable knowledge and evidence.
