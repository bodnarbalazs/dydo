# dydo 3.0 Skill Model Simplification Assimilation

This brief records what the skill-model simplification changed, what its eight Issues taught, and what
the human's own pass must still write. The Project cut the compiler's leftover "role" model and every
customisation path the product's one human had abandoned: a skill template is now one shipped
`skill-<name>.template.md` whose frontmatter is the whole metadata and whose compiled output derives
from the embedded set alone.

## What changed

Eight Issues merged serially into `feature/simplify-skill-model` from `9875c9a6`. At the last of them,
`bda87ba9`, the branch stood at 155 files changed, 1,870 insertions and 8,642 deletions against that
base; the closeout lane took it to 160 files, 2,098 insertions and 8,667 deletions.

- **S-1 (DYD-76, `902443ca`)** — `ModelsConfig.Roles` became `Agents` behind `models.agents`,
  `ResolveModel` takes an agent name, and `UpgradeLegacyPlannerRole`, `UpgradeLegacyOpenAiTierDefaults`
  and `MigrateHashFormat` went with their tests. A `dydo.json` still carrying the old key now binds
  nothing, and the first command that rewrites the file drops it unread.
- **S-3 (DYD-77, `b321897f`)** — every `Generate*Md` reads its embedded template and lets
  `FileNotFoundException` propagate; ten `GenerateFallback*Md` bodies and nine tests are gone. A
  missing template fails the command instead of scaffolding a stale C# copy of the document.
- **S-2 (DYD-78, `a72d34f8`)** — the project-local template layer went whole: no
  `dydo/_system/templates/` scaffold, override, custom skill, include re-anchoring, template hash,
  `mode-*` handling or `--force`. The 35-file mirror left this repository and 34 `frameworkHashes`
  keys were pruned. A project's skills come from the shipped set only, and `dydo check` now reports
  every file in a surviving mirror as missing required frontmatter.
- **S-4 (DYD-79, `9f154884`)** — `dydo model cap|status|uncap`, `ModelCapService`, `models.fallback`
  and the guard's expiry restore are gone. `dydo help` lists no `model` command and a capped model is
  no longer a dydo concept.
- **S-5 (DYD-80, `daa55cfd`)** — `paths` (with `pathSets`), tool-scoped file nudges, `models.efforts`
  and the project `name` are gone. A nudge is a bash-command regex with `pattern`, `message` and
  `severity`; a tool-scoped block is now evaluated on the bash lane, where its glob pattern is an
  inert or invalid regex.
- **S-6 (DYD-81, `75a5bb51`)** — the compiler names what the glossary names: `SkillTemplate`,
  `SkillTemplateService.DiscoverSkills`/`Parse`, `SyncAgent`/`SyncCodexAgent`/`SyncSkill`,
  `RetiredSkills`. Proved behaviour-free: `init claude` + `init codex --join` + `sync` in two scratch
  directories, base `daa55cfd` against the candidate, `diff -r` over `.claude`, `.codex` and `.agents`
  silent across 115 files a side.
- **S-7 (DYD-82, `f8d7a251`)** — `name:` replaced `mode:` on every shipped skill template and
  `SkillTemplateService.Parse` requires it to equal the filename slug. `dydo sync` now fails with an
  `InvalidDataException` naming the file and the expected slug rather than compiling a nameless
  template.
- **S-8 (DYD-83, `bda87ba9`)** — DYD-75 items 2 to 4. `web: true` compiles `WebFetch, WebSearch` on
  Claude and a trailing `[tools]` / `web_search = true` on Codex; the research scout resource became
  `Templates/skill-scout.template.md`, a read-only, web-enabled, non-delegating agent; `argument-hint`
  compiles to Claude's `argument-hint:` and Codex's `interface.default_prompt`, and
  `agents/openai.yaml` is written when a skill is explicit, carries a hint, or both, and removed when
  it declares neither. `handoff` and `teach` carry the upstream hint texts.
- **Closeout lane (`966525ac`, reviewed with zero findings)** — the Gate A findings that fell inside
  this Project's licence: `dydo init` no longer prints the removed `paths` guidance; `test-writer`
  joined `RetiredSkills` and the sweep now takes each retired skill's `agents/openai.yaml` and the
  folder it was holding open on both hosts; dead references to project-local templates, path sets,
  model caps and template update's template half left code comments, command help, both READMEs, the
  two hash-tracked doc twins and four `dydo/` documents.

The human's migration for a 2.x or early-3.0 project is
[Migrate from dydo 2.x to 3.x](../../guides/migrating-dydo-2x-to-3x.md).

## What was learned

- **A quoted-key grep proves one spelling absent, not a concept.** Gate R7 could not see two of its
  own targets: `Console.WriteLine("  \"paths\": {")` escapes the quotes, and a test fixture's
  `paths = new { source = …, tests = … }` never quotes the key at all. Both survived every residue run
  and were found by reading, in the closeout audit.
- **The serial-consequence rule (plan §4 preamble) is what let eight Issues share hot files.** An
  Issue's surface is its row plus what its cut demonstrably breaks — a compile error, a test its base
  had green, or a hit from its own Gate R — each listed with a one-line reason for the reviewer.
  `SyncCommand.cs`, `ConfigFactory.cs`, `dydo.json` and `customizing-roles.md` passed through five to
  eight Issues without an ownership fight.
- **`frameworkHashes` drift is silent until the template changes.** At `9875c9a6` the stored hash for
  `reference/about-dynadocs.md` (`e531b2c5…`) matched neither the installed document nor the shipped
  template, which were byte-identical at `060c1bd1…`; `template update` took the equality path and
  reported the file already current. The moment S-2 edited the template the same run reported the
  installed copy user-edited and skipped it, so the stored hash had to be reconciled to the on-disk
  value before the shipped edit could cross.
- **A negative assertion can re-introduce the literal it denies.** The base asserted that the
  `dotnet run` nudge pattern contained the retired plural of "role"; inverting that into a
  `DoesNotContain` would have kept the same string literal and Gate R1 would still have hit it. S-4
  asserted instead that the pattern's command alternation equals the set `Program.cs` registers — a
  stronger test that names no retired word.
- **Residue scans must be scoped to tracked sources.** Stale coverage XML under the gitignored
  `DynaDocs.Tests/TestResults` produces hits that no source file explains.
- **Two harness defects, neither fixed here.**
  `DynaDocs.Tests/coverage/run_tests.py::copy_dirty_files` reads `git status --porcelain` and, for a
  rename entry `R  old -> new`, keeps only `new`: it never deletes `old` in the temp worktree, so an
  uncommitted rename fails to compile under the isolated runner. The same loop skips an untracked
  directory, which porcelain reports as one entry that `is_file()` rejects — `git add` a new fixture
  directory before running it.
- **The baseline red set was never this Project's.** Fourteen integration tests were red at
  `9875c9a6` and twelve from S-2 on, in four groups: `InitCheckIntegrationTests`,
  `FixCommandIntegrationTests`, `ChangelogStructureTests`, and one `DocumentationTests` case. S-2
  deleted two as moot (`FreshInit_TemplatesAreExcludedFromCheck` and
  `InstalledTemplateParityTests.MattDerivedTemplates_ShippedSourceEqualsInstalledCopy`).
- **Six plan review rounds preceded delivery.** The human's standing rule from 2026-09-02 is two:
  fold the findings in and start.

## What remains — the human's pass

The Project's no-rewrite rule allowed a frontmatter key, a straight reference rename, the deletion of
a line, row or section describing a cut feature, one verbatim body move and one dead-link replacement.
Everything below needs words, and the words are the human's.

### The LC project

LC's migration is documented, not executed: the human runs the guide. Gate A's migration lens measured
that tree — `dydo/_system/templates/` holds thirteen 2.x `mode-*` copies and five stale resource
copies; `_system/notion_sync_spine/` is 115 files and 243 `dydo check` findings, to scan-exclude or

Of its template additions, `extra-complete-gate.md` and `extra-test-quality.md` match no shipped tag,
`extra-verify`, `extra-review-checklist`, `extra-review-steps` and `extra-test-guidance` still work,
and `extra-must-reads` is new and unfilled. `dydo template update` there overwrites four hash-clean
reference documents, creates `linear-workspace-standard.md` and `working-tree-contract.md`, deletes
`guides/how-to-use-docs.md`, prunes 20 hashes and adds two default nudges; `dydo sync` sweeps
`planner`, `orchestrator`, `run-sprint.js` and the reviewer's `merge-sprint.md` and `plan.md`, plus —
with the closeout fix — `test-writer`'s four artifacts and any retired skill's `agents/openai.yaml`.

### Landing the branch

The main checkout's uncommitted pass is the human's to discard: 37 modified files, keeping
`dydo/.obsidian/workspace.json`. That pass writes `skill:` where S-7 writes `name:`, so the recorded
rename for a merge conflict is
`sed -i 's/^mode: /name: /; s/^skill: /name: /' Templates/skill-*.template.md`; a template left
carrying either key fails `dydo sync` with
`System.IO.InvalidDataException: Skill template 'skill-x.template.md' has no 'name:'; expected 'name: x'.`
Master's uncommitted edits touch the `skill-orchestrator`, `skill-planner` and `skill-test-writer`
templates and the `dydo/_system/templates` mirror; committed against the feature branch they would be
modify/delete conflicts. Then `feature/simplify-skill-model` lands on `DYD-64-human-pass`.
