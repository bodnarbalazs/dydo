# Engineering

8 skills for the craft: diagnosing, shaping and designing code.

- **codebase-design** (model-invoked): Shared vocabulary for designing deep modules. Use when the human wants to design or improve a module's interface, find deepening opportunities, decide where a seam goes, make code more testable or AI-navigable, or when another skill needs the deep-module vocabulary.
- **create-verification-skill** (user-invoked): Generate a project-local verification skill that drives the app the way a user does, through a deterministic control CLI and a feature map.
- **diagnosing-bugs** (model-invoked): Diagnosis loop for hard bugs and performance regressions. Use when the human says "diagnose"/"debug this", or an Issue reports something broken/throwing/failing/slow.
- **domain-modeling** (model-invoked): Build and sharpen a project's domain model. Use when discussing codebase terminology, writing or editing the glossary, or recording or editing a Decision Record.
- **improve-codebase-architecture** (user-invoked): Scan a codebase for deepening opportunities, present them as a visual HTML report, then grill through whichever one you pick.
- **maintain-verification-skill** (model-invoked): Keep a project's verification skill and feature map true to the running app. Use when a drive contradicts the feature map, a touched area has no map file, or a landing wants the whole map audited.
- **prototype** (model-invoked): Build a throwaway prototype to answer a design question. Use when the human wants to sanity-check whether a state model or logic feels right, or explore what a UI should look like.
- **wizard** (model-invoked): Human-only setup, credentials or cutover steps need a repeatable interactive bash procedure; the Enablement captain uses this method.
