# Muster

Set them up for success.

The Chief of Staff completes this checklist with the user before activation.

- [ ] Request each admiral's report using the block below.
- [ ] Show each intent read-back verbatim, separately from work; obtain the user's corrections.
- [ ] Present current and foreseeable questions with context, options and recommendations; record
      the user's answers and why.
- [ ] Resolve operational blockers while the user is present; verify each fix with evidence.
- [ ] Exercise needed permissions through safe, authorized operations where supported: admiral
      contact, each session's Linear writes and feature-branch merge capability. Record actual
      results. An unprotected branch proves no merge permission. Never perform a dummy merge.
- [ ] Keep unsupported exercises and unresolved items as gaps. Obtain explicit user agreement to
      exclude or defer dependent work and settle a runnable alternative; revise the work list.
- [ ] Post each Project's night orders using the template below.
- [ ] Obtain every included admiral's confirmation that its agreed work is runnable under those orders.

Ready means all boxes are complete. Return to `overnight-mode` for activation.

## Request to each admiral

```text
The user's muster request for <date>, <Project>. Return:
Intent: run in-your-own-words on the user's goals and purpose, separately from tasks.
Work: proposed order, first runnable item and stop line.
Questions: already-blocking and foreseeable calls; context, options and recommendation for each.
Blockers: operational obstacle, proposed fix and evidence needed to verify it.
Permissions: exact actions needed and a safe exercise for each, or the unsupported gap.
```

## Present to the user

Copy once per Project; settle the calls before proceeding.

```text
<Project> — <admiral thread link>
Intent, as the admiral reads it: <verbatim read-back>
Work: <ordered tasks, first runnable item>
Stop line: <boundary and decisions reserved for you>
Your calls: <question; context; options; recommendation>
Unblock now: <obstacle; proposed fix; verification evidence>
Permissions: <exact action; safe exercise; observed result or gap>
```

## Night orders — Project update

```text
Night orders, <date>; expire at morning brief and override conflicting standing orders.
Intent: <read-back with the user's corrections>
Work: <agreed order and first runnable item>
Answered: <question → answer and why>
Unblocked: <obstacle → fix and verification evidence>
Permissions: <authorized actions; actual exercise evidence; remaining gaps>
Deferred: <item; explicit user agreement; settled runnable alternative>
Stop line: <boundary and decisions reserved for the user>
```
